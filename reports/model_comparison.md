# Порівняння якості моделей

**Задача:** передбачення оформлення строкового депозиту клієнтом банку (бінарна класифікація)
**Основна метрика:** F1-score для класу `yes` (з огляду на дисбаланс класів 88.7% / 11.3%)
**Train/test спліт:** 80/20, stratified (32940 / 8236 рядків)

| Модель | Гіперпараметри | F1 (train) | F1 (test) | Коментар |
|---|---|---|---|---|
| **Logistic Regression** | `max_iter=1000`, `class_weight='balanced'`, `random_state=42` | 0.4539 | 0.4649 | Train ≈ test — перенавчання відсутнє, модель добре узагальнює. Проста, повністю інтерпретована через коефіцієнти. Якість помірна — F1 нижчий за дерево і бустинг. **Варто використовувати** як прозорий baseline. Ідеї для покращення: підбір регуляризації (`C`, L1/L2), видалення мультиколінеарних макроознак, поліноміальні ознаки для нелінійних залежностей (наприклад, `age`). |
| **kNN** | `n_neighbors=15` (масштабовані ознаки, 58 колонок) | 0.4100 | 0.3634 | Train дещо вищий за test — легке перенавчання, очікуване через високу розмірність ознак ("curse of dimensionality"), що псує метрику відстані. Найслабша модель з чотирьох за F1. **Наразі не рекомендується** для продакшену в такому вигляді. Ідеї для експериментів: зменшення розмірності (PCA, прибрати дублюючі ознаки `age`/`age_group`, `month`/`quarter`), підбір оптимального `k` через крос-валідацію, спробувати `weights='distance'`. |
| **Decision Tree** | `max_depth=6`, `min_samples_leaf=50`, `class_weight='balanced'`, `random_state=42` | 0.4809 | 0.5011 | Train ≈ test (test навіть трохи вищий) — перенавчання відсутнє завдяки обмеженню глибини та мінімальної кількості зразків у листі. **Найкращий F1 серед усіх чотирьох моделей.** Дуже висока інтерпретованість — дерево можна повністю візуалізувати. **Рекомендується** як сильний кандидат, особливо з огляду на вимогу пояснюваності. Ідеї: підбір `max_depth`/`min_samples_leaf` через GridSearch, перевірка стабільності через крос-валідацію. |
| **LightGBM** | `n_estimators=200`, `learning_rate=0.05`, `max_depth=5`, `class_weight='balanced'`, `random_state=42` | 0.4914 | 0.4962 | Train ≈ test — стабільна модель без перенавчання. Найкращі ROC-AUC (0.8126) і PR-AUC (0.4800) серед усіх — краще ранжує клієнтів за ймовірністю. F1 трохи нижчий за Decision Tree при порозі 0.5, ймовірно поріг не оптимальний саме для цієї моделі. **Рекомендується** як сильний кандидат на фінальну модель, особливо якщо важливе ранжування (пріоритизація дзвінків). Ідеї: підбір оптимального порогу класифікації через PR-curve, тюнінг гіперпараметрів (GridSearch/Optuna), SHAP для пояснення передбачень. |

## Загальний висновок

- **Перенавчання відсутнє в жодної з моделей** — різниця train/test F1 незначна для всіх, окрім легкого ефекту в kNN.
- **Лідери за F1:** Decision Tree (0.5011) і LightGBM (0.4962) — приблизно на одному рівні, з різними сильними сторонами: Decision Tree простіша й наочніша, LightGBM краще ранжує за ймовірністю (вищий ROC-AUC/PR-AUC) і має більший потенціал для покращення через тюнінг.
- **kNN — найслабший кандидат** у поточній конфігурації, потребує суттєвого доопрацювання (зменшення розмірності) перш ніж розглядатись серйозно.
- **Logistic Regression** — надійний, стабільний baseline, але поступається за якістю нелінійним моделям; цінність — максимальна прозорість.

**Наступні кроки:** підбір оптимального порогу класифікації для LightGBM/Decision Tree через PR-curve, тюнінг гіперпараметрів через крос-валідацію, та інтерпретація фінальної моделі (feature importance / SHAP) для пояснення замовнику.
