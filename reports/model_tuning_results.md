# Підсумкові результати тюнінгу моделей

**Задача:** передбачення оформлення строкового депозиту клієнтом банку (бінарна класифікація)
**Основна метрика:** F1-score для класу `yes`
**Train/test спліт:** 80/20, stratified (~32940 / ~8236-8238 рядків)

---

## 1. Logistic Regression

| Етап | Гіперпараметри | F1 (test) | Precision (yes) | Recall (yes) |
|---|---|---|---|---|
| Baseline (ручні параметри) | `max_iter=1000`, `class_weight='balanced'` | 0.4649 | 0.36 | 0.65 |
| Після GridSearchCV | `C=10`, `penalty='l1'`, `solver='liblinear'` | 0.4647 | 0.36 | 0.65 |
| **Після підбору порогу** | ті самі + **поріг = 0.654** | **0.5168** | 0.45 | 0.60 |

**Метод тюнінгу:** GridSearchCV (`C`: [0.001–100], `penalty`: [l1, l2], 5-fold CV) — практично не покращив модель (найкращий CV F1 = 0.4512).
**Підбір порогу:** дав найбільший приріст серед усіх кроків тюнінгу (+0.052 F1) — зсув порогу від 0.5 до 0.654 суттєво покращив баланс precision/recall.
**Висновок:** стабільна, повністю інтерпретована модель (коефіцієнти). Не найкраща за якістю, але хороший baseline і кандидат, якщо пріоритет — прозорість пояснення замовнику.

---

## 2. kNN

| Етап | Гіперпараметри | F1 (test) | Precision (yes) | Recall (yes) |
|---|---|---|---|---|
| Baseline (58 ознак) | `n_neighbors=15` | 0.3634 | 0.61 | 0.26 |
| Після зменшення розмірності (52 ознаки) + GridSearchCV | `n_neighbors=5`, `weights='uniform'` | 0.3859 | 0.56 | 0.29 |
| **Після підбору порогу** | ті самі + **поріг = 0.400** | **0.4295** | 0.41 | 0.45 |

**Метод тюнінгу:** прибрано дублюючі ознаки (`age_group`, `quarter` — 58→52 колонки), GridSearchCV по `n_neighbors`/`weights` (найкращий CV F1 = 0.3737).
**Підбір порогу:** приріст +0.044 F1.
**Висновок:** найслабша модель з чотирьох за всіма метриками (F1, ROC-AUC=0.7341, PR-AUC=0.3369). Фундаментальна причина — розріджені One-Hot ознаки погано поєднуються з метрикою відстані ("curse of dimensionality"). Не рекомендується для використання в поточній конфігурації ознак.

---

## 3. Decision Tree

| Етап | Гіперпараметри | F1 (test) | Precision (yes) | Recall (yes) |
|---|---|---|---|---|
| Baseline (ручні параметри) | `max_depth=6`, `min_samples_leaf=50` | 0.5011 | 0.42 | 0.63 |
| Після GridSearchCV | `max_depth=6`, `min_samples_leaf=20`, `min_samples_split=2` | 0.4996 | 0.42 | 0.62 |
| **Після підбору порогу** | ті самі + **поріг = 0.741** | **0.5157** | 0.49 | 0.55 |

**Метод тюнінгу:** GridSearchCV (84 комбінації `max_depth`/`min_samples_leaf`/`min_samples_split`, 5-fold CV) — знайшов практично ту саму конфігурацію, що й початкова ручна (найкращий CV F1 = 0.4702). Тюнінг гіперпараметрів не дав приросту.
**Підбір порогу:** приріст +0.016 F1.
**Висновок:** висока інтерпретованість (повна візуалізація дерева рішень), результат близький до Logistic Regression після підбору порогу. Хороший кандидат, якщо потрібна максимально наочна логіка прийняття рішень для нетехнічного замовника.

---

## 4. LightGBM (Gradient Boosting)

| Етап | Гіперпараметри | F1 (test) | Precision (yes) | Recall (yes) |
|---|---|---|---|---|
| Baseline (ручні параметри) | `n_estimators=200`, `learning_rate=0.05`, `max_depth=5` | 0.4962 | 0.40 | 0.66 |
| Після RandomizedSearchCV | `n_estimators=500`, `learning_rate=0.01`, `max_depth=-1`, `num_leaves=63`, `min_child_samples=10`, `subsample=0.8`, `colsample_bytree=0.7` | 0.5046 | 0.41 | 0.65 |
| Після Hyperopt (Bayesian Optimization) | `n_estimators=150`, `learning_rate=0.0187`, `max_depth=9`, `num_leaves=70`, `min_child_samples=10`, `subsample=0.972`, `colsample_bytree=0.773` | 0.5054 | 0.41 | 0.65 |
| **Після підбору порогу (Hyperopt-модель)** | ті самі + **поріг = 0.600** | **0.5340** | 0.47 | 0.63 |

**Метод тюнінгу — порівняння двох підходів (однаковий бюджет: 40 ітерацій):**

| | RandomizedSearchCV | Hyperopt (Bayesian) |
|---|---|---|
| CV F1 | 0.4836 | 0.4810 |
| Test F1 | 0.5046 | 0.5054 |
| ROC-AUC | 0.8127 | 0.8173 |
| PR-AUC | 0.4894 | 0.4944 |
| Кількість дерев | 500 | 150 |

Hyperopt дав трохи кращий результат за всіма метриками при значно компактнішій моделі (150 дерев проти 500) — байєсівська оптимізація ефективніше використала бюджет ітерацій, спрямовуючи пошук на основі попередніх результатів, на відміну від випадкового семплінгу в RandomizedSearchCV.

**Підбір порогу:** приріст +0.029 F1 понад тюнинговану модель.
**Висновок:** **найкраща модель з чотирьох за підсумковим F1 (0.5340), а також за ROC-AUC (0.8173) і PR-AUC (0.4944)**. Тюнінг гіперпараметрів для бустингу виявився значно ефективнішим, ніж для інших моделей — сумарний приріст від baseline до фінальної версії: +0.038 F1 (0.4962 → 0.5340).

## Підсумковий рейтинг моделей (найкращий F1 з оптимальним порогом)

| Місце | Модель | F1 (test) | ROC-AUC | PR-AUC | Оптимальний поріг |
|---|---|---|---|---|---|
| 1 | **LightGBM (Hyperopt)** | **0.5340** | 0.8173 | 0.4944 | 0.600 |
| 2 | Logistic Regression | 0.5168 | 0.8012 | 0.4462 | 0.654 |
| 3 | Decision Tree | 0.5157 | ~0.799 | ~0.449 | 0.741 |
| 4 | kNN | 0.4295 | 0.7341 | 0.3369 | 0.400 |

## Ключові висновки з усієї серії експериментів

1. **Підбір порогу класифікації — найефективніший і найдешевший спосіб покращення F1** для всіх без винятку моделей (приріст від +0.016 до +0.052), значно ефективніший за тюнінг гіперпараметрів для Logistic Regression і Decision Tree, де тюнінг гіперпараметрів практично не дав приросту.
2. **Тюнінг гіперпараметрів дав відчутний ефект тільки для LightGBM** — через більшу кількість параметрів і складніші взаємодії між ними в бустингу є більше простору для покращення через систематичний пошук.
3. **Hyperopt (Bayesian Optimization) показав себе ефективнішим за RandomizedSearchCV** при однаковому бюджеті ітерацій — трохи краща якість при суттєво компактнішій моделі (менше дерев).
4. **Після підбору порогу розрив між моделями суттєво звузився**: Logistic Regression і Decision Tree практично зрівнялись (0.5168 vs 0.5157), обидва наблизились до LightGBM (0.5340) — важливий висновок для вибору фінальної моделі: якщо пріоритет — простота й пояснюваність, простіші моделі майже не поступаються складнішим за якістю.
5. **kNN залишається найслабшим кандидатом** на всіх етапах — фундаментальна причина в природі даних (розріджені One-Hot ознаки погано поєднуються з метрикою відстані), а не в конкретних гіперпараметрах чи порозі.

**Рекомендація:** **LightGBM (Hyperopt, поріг=0.6)** — фінальний кандидат за якістю. Якщо для замовника критична максимальна пояснюваність без додаткових інструментів (SHAP), альтернативний кандидат — **Decision Tree** (поріг=0.741), що дає порівнянну якість при повній прозорості логіки рішень.
