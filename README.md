Bank Term Deposit Prediction

Проєкт з курсу "Machine Learning для людей" — побудова моделі, що передбачає, чи оформить клієнт банку строковий депозит (term deposit) за результатами телефонної маркетингової кампанії.

Задача
Ролі: Data Scientist в банку. Мета — побудувати модель бінарної класифікації, яка передбачає ймовірність того, що клієнт підпише строковий депозит (y), і пояснити замовнику, чому модель приймає такі рішення — без цього неможливий перехід до впровадження моделі в продакшн.
Задача типова для широкого кола доменів: передбачення купівлі продукту, підписки на сервіс, конверсії користувача — тому підхід і методологія переносяться на суміжні задачі.

Дані
Джерело: UCI Bank Marketing Dataset (Kaggle) — bank-additional-full.csv
Дані прямих маркетингових дзвінків португальської банківської установи: демографія клієнта, деталі останнього контакту, історія попередніх кампаній, соціально-економічний контекст.
41 188 записів, 20 ознак + цільова змінна y
Сильний дисбаланс класів: no — 88.7%, yes — 11.3%
Ознака duration виключена з моделювання — її значення невідоме до здійснення дзвінка (data leakage)

Що зроблено
EDA — аналіз розподілів, пропущених значень (закодованих як 'unknown'), кореляцій, формулювання гіпотез щодо впливу ознак на y
Препроцесинг — обробка спеціальних кодів (pdays=999), групування рідкісних категорій, обробка outliers (campaign), feature engineering (was_contacted_before, age_group, quarter, no_credit_info та ін.)
Тренування 4 моделей: Logistic Regression, kNN, Decision Tree, LightGBM (градієнтний бустинг)

Тюнінг гіперпараметрів
Logistic Regression, Decision Tree, kNN — GridSearchCV
LightGBM — порівняння RandomizedSearchCV (sklearn) і Hyperopt (Bayesian Optimization)
Підбір оптимального порогу класифікації для кожної моделі (максимізація F1)
Інтерпретація моделі через SHAP (TreeExplainer, summary plots, waterfall plot для окремих кейсів)
Аналіз помилок — порівняння профілів клієнтів у False Negative / False Positive, виявлення причин і рекомендацій щодо покращення

Результати
Метрика: F1-score для класу yes (обрана через сильний дисбаланс класів)

Модель	              F1 (оптимальний поріг)	   ROC-AUC	   PR-AUC

Висновки
Найкраща модель — LightGBM з гіперпараметрами, знайденими Hyperopt (Bayesian Optimization показала себе ефективнішою за RandomizedSearchCV при однаковому бюджеті ітерацій — краща якість при вдвічі-втричі компактнішій моделі)
Підбір порогу класифікації дав більший приріст F1, ніж тюнінг гіперпараметрів для трьох з чотирьох моделей — дешевий і недооцінений важіль покращення
Після підбору порогу прості моделі (Logistic Regression, Decision Tree) майже зрівнялись з бустингом за якістю — якщо для замовника критична прозорість пояснення, ці моделі — повноцінна альтернатива
SHAP-аналіз показав, що ключові драйвери рішення — макроекономічний контекст (сумарно), історія попередніх контактів з клієнтом (poutcome, was_contacted_before) та інтенсивність дзвінків у поточній кампанії; вбудований feature_importances_ LightGBM спотворював цю картину через мультиколінеарність і шумові ознаки (day_of_week)
Аналіз помилок показав структурну межу моделі: вона систематично пропускає позитивні кейси серед "холодних" клієнтів без історії контакту і хибно впевнена в частині "ідеальних" теплих лідів, які все ж відмовляються — це свідчить про брак ознак фінансового профілю клієнта, а не про недолік моделі чи налаштувань

Що можна покращити далі
Додати ознаки фінансового профілю клієнта (баланси рахунків, інші продукти банку) — найбільший потенціал прориву за поточну межу F1≈0.53
Окрема модель/калібрування для сегменту клієнтів без історії попередніх контактів (94-96% датасету)
Перевірити калібрування ймовірностей (CalibratedClassifierCV)
У продакшені — використовувати модель для ранжування пріоритету дзвінків, а не жорсткого бінарного рішення
